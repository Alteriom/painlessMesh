# 02-feature — add a capability

One run is one capability: a new API, option, package type or example, agreed on paper before it is built. A spec comes first because what a node puts on the wire, and what a sketch has to call, cannot be taken back once a version ships.

Stages, in order — the table with inputs, outputs and checks is [CONTEXT.md](CONTEXT.md):

1. [Spec](stages/01_spec/CONTEXT.md) — what, why, the API, the wire, the version class.
2. [Implement](stages/02_implement/CONTEXT.md) — build what the spec says.
3. [Test](stages/03_test/CONTEXT.md) — prove it at the level the spec named.
4. [Docs](stages/04_docs/CONTEXT.md) — documents, changelog, pull request.

Stop after each stage until a person has read its output.
